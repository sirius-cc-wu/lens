# Risk List

| ID | Risk | Type | Likelihood | Impact | Mitigation and evidence needed |
|---|---|---|---|---|---|
| `R-01` | A PlantUML server may expose diagram source, become unavailable, rate-limit requests, or change response behavior. | Technical / adoption | Medium | High | E1 validated live, invalid, unavailable, and delayed server responses; C1 and C2 use a controlled server for deterministic browser evidence. ADR-017 and C7 fix one destination per session, support a private or self-hosted server through `LENS_PLANTUML_SERVER`, forbid fallback after a configured-server failure, and retain the 10-second timeout, 2 MiB response limit, visible source, and per-diagram retry. C7 adds server normalization, removed-route, CLI, and browser evidence. Public-service availability and disclosure remain residual risks for zero-configuration sessions. |
| `R-02` | Unsanitized Markdown or SVG can execute unsafe browser content. | Technical / security | Medium | High | E1 escapes raw Markdown HTML, serves PlantUML SVG only as an image, and sets a restrictive content security policy. P10 parses only leading YAML frontmatter and escapes scalar, nested, and unknown metadata values before inserting them into the page; malformed YAML receives a fixed correction message. C9 renders a fixed source-link indication inside an ordinary anchor and uses compiled-browser checks to verify its visible accessible name, hover behavior, external and fragment preservation, and continued page usability after refresh. Expand malicious-content fixtures before future construction broadens the parser surface. |
| `R-03` | File and directory resolution can expose files outside the requested repository. | Technical / security | Low | High | E2 canonicalizes the document root, excludes discovered symbolic links and hidden entries, and serves only known document identifiers. D1 through D4 establish and verify the nearest supported repository boundary for file, directory, and current-directory targets while retaining `--scope target` for an explicit narrow session. ADR-020 and R2 replace the searchable catalog with a typed, fixed `KnownDocuments` route lookup; browser query values are ignored rather than interpreted as paths. ADR-021 requires generated editor links to reuse the same fixed root without adding a browser path route. C8 resolver, Markdown, target, and refresh checks verify canonical containment, readable regular-file classification, malformed encoding, absolute and out-of-root rejection, hidden components, file and directory symbolic links, document precedence, and cross-platform URL serialization. C9 compiled-browser checks confirm that only qualifying paths receive editor URLs and that neither a source route nor a document route exposes source contents. |
| `R-04` | "Display the codebase's code and document" is too ambiguous to estimate or scope. | Product | Low | Medium | ADR-004 defines V1 as documentation-only. D5 refines post-V1 `UC-06`, and ADR-021 selects a bounded handoff: qualifying relative files open through VS Code's registered URL handler while Lens remains a documentation-only HTTP viewer. Configurable editors, source serving, folder opening, and source-position fragments remain out of scope. |
| `R-06` | Browser launch and process lifetime vary across desktop, container, and headless environments. | Technical | Medium | Medium | P7 tests the Linux `xdg-open`, macOS `open`, and Windows `cmd /C start` command constructions. C15 keeps launch in the invoking client, preserves the manual URL when launch fails, and starts detached Unix or Windows service candidates through native process flags. The compiled-browser fixture proves that the client exits before page use and refresh. C16 adds native Rust pull-request checks; native desktop handoff remains a release-readiness check. |
| `R-07` | A standalone distribution could be harder to install than an editor plugin. | Schedule / adoption | Medium | Medium | P2 adds a target-bound archive with a SHA-256 checksum, README, and license so users do not need a Rust toolchain. P7 generalizes the archive to native Linux, macOS, and Windows targets, preserves `lens.exe` on Windows, and retains the no-overwrite and extraction checks. P8 builds those artifacts on native tag-release runners and publishes them only after all three jobs succeed; native desktop and downloaded-archive testing remain release evidence. |
| `R-08` | Automatic refresh could rescan or expose files outside the authorized document set, replace readable content during a partial save, or trigger browser reload loops. | Technical / security | Medium | High | ADR-007 and C4 poll only canonical paths fixed at session creation, retain the last successful rendering on failed reads, and expose a revision-only current-document query. Unit tests cover changed and missing known files plus an unknown revision path; `BTE-01` saves the displayed document and verifies automatic refresh without `page.reload()`. Polling large document sets remains a residual performance risk. |
| `R-09` | Eager discovery, rendering, and repeated refresh reads can make unusually large documentation trees impractical. | Technical / performance | Medium | High | ADR-020 and R2 remove complete-catalog response markup, search scans, pagination, and navigation browser work. D4 exposes and verifies `--scope target` for users who need a narrower discovery and refresh boundary. C16's optimized one-document reference grew from 5,264 KiB resident memory (RSS) to 12,804 KiB at 50 retained sessions, about 117 KiB per added session after first-use initialization, and used 70 ms CPU over five idle seconds for 50 pollers. Those results defer close detection or idle retirement for ordinary use but do not bound lifetime growth. Improvement 14 still requires repeatable 1,000- and 10,000-document startup, response, memory, and refresh measurements before changing discovery or polling. |
| `R-10` | Removing renderer modes can break CLI and Rust API consumers and leave users who relied on local-command or disabled rendering without an equivalent workflow. | Product / compatibility | Medium | High | C7 removes `--renderer`, `RendererMode`, and the second `serve` argument together. CLI and type-bound tests verify both breaking surfaces; README migration guidance directs former local users to a private or self-hosted server and states that there is no no-rendering replacement. Pending release notes identify the CLI and library break before release. |
| `R-11` | Automatic service startup, concurrent commands, a crashed process, or stale discovery state could create competing background Lens processes, hang a client, lose an accepted request, or report false success. | Technical / reliability | Low | High | C13 atomically claims the per-user endpoint and safely recovers verified stale Unix sockets. C14 retains one idempotent outcome per `RequestId`. C15 verifies concurrent first commands, automatic startup, retries, target rejection, browser failure, and continued page availability after client exit. C16 verifies the acknowledgment timeout mechanically and measured its production path at 10,005 ms; startup is bounded at three seconds. Native pull-request checks and the manual crash/restart walkthrough remain release gates. A service crash still ends all URLs it owns by design. |
| `R-12` | A long-lived process hosting several viewing sessions could accept another user's command or leak document roots, target scopes, source-link authority, or PlantUML configuration across repositories. | Technical / security | Low | High | C12 bounds versioned frames at 64 KiB and preserves native paths. C13 restricts Unix sockets and verifies peer user identity before decoding; the Windows named pipe is user-SID-specific, rejects remote clients, and permits only that user and LocalSystem. C14 and C15 verify independent roots and PlantUML servers, a new listener per request, no reachable session on rejection, and no browser attempt for rejected targets. Native Linux, macOS, and Windows Rust checks are pull-request gates. Residual risk is concentrated in future changes to endpoint policy or session authority rather than known cross-session sharing. |

`R-01` through `R-04` drove the first elaboration iteration. `R-11` and `R-12`
drove S1 through C17 delivery of the background viewer service. `R-09` remains
the primary performance risk for large document sets and unbounded service
lifetimes.
